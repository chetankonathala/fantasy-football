## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline label spacing |
| sm | 8px | Compact element spacing, list item gaps |
| md | 16px | Default element spacing, card inner padding |
| lg | 24px | Section padding, card-to-card gaps |
| xl | 32px | Layout column gaps, page horizontal padding |
| 2xl | 48px | Major section breaks, hero verdict top margin |
| 3xl | 64px | Page-level vertical rhythm on home centered layout |

Exceptions:
- Touch target minimum for scoring format selector buttons: 44px tall (accessibility requirement — override sm/md as needed)
- Search autocomplete dropdown items: 44px min-height (tap-safe on mobile)

**Source:** CONTEXT.md §Frontend Styling (dark mode, Tailwind); RESEARCH.md §Architecture Patterns; defaults applied for all token values.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 36px | 700 (bold) | 1.1 |

Notes:
- Display role is used exclusively for the verdict word (START / SIT / FLEX) — the hero element on the recommendation card.
- Heading role is used for the player name on the player detail page and section labels on the card.
- Label role is used for signal row labels (Matchup Grade, Injury Status, Snap %, etc.) and the data freshness stamp.
- Body role is used for reasoning factor text and autocomplete suggestion lines.
- Two weights in play for body/label (400) and heading/display (600/700). Display uses 700 to maximize verdict impact.

**Source:** CONTEXT.md §Page Structure ("Verdict is the hero element — big, bold, color-coded"); defaults applied for sizes and line heights.

## Component Inventory

### SearchBar (`components/SearchBar.tsx`)

- `"use client"` component
- Input: full-width on home (`/`), constrained to ~320px in nav header
- Placeholder: "Search players..."
- Trigger: 2 characters minimum before any API call fires
- Debounce: 300ms after last keystroke (via `use-debounce`)
- Dropdown: absolute-positioned panel, `z-50`, background `#111827`, rounded-md, shadow-lg
- Suggestion item height: 44px min, padding `md` (16px) horizontal, `sm` (8px) vertical
- Suggestion layout: `{full_name} — {position}, {team}` (e.g., "Justin Jefferson — WR, MIN")
- Max 5 items shown; no scroll — list is always visible in full
- Empty match: shows "No players found" as a disabled item, same panel styling
- Loading state: single animated pulse skeleton item in dropdown during fetch
- Keyboard: arrow keys navigate list, Enter selects, Escape closes
- Accent (`#004C54`) background tint on hovered/focused item

### Home Page (`app/page.tsx`)

- Server component
- Vertically + horizontally centered layout using flexbox (`min-h-screen items-center justify-center`)
- App name: "Fantasy Advisor" — Display heading, weight 600, white, above search
- Subtitle: "Start/Sit clarity, instantly." — Body, silver `#A5ACAF`, below app name
- SearchBar centered, width `min(100%, 480px)`
- No other content — no featured players, no recent searches, no footer

### Nav/Header (in `app/layout.tsx`)

- Fixed top, full-width, background `#111827`, border-bottom `#004C54` 1px
- Left: app name "Fantasy Advisor" — Label size (14px), semibold, white, links to `/`
- Right: SearchBar, constrained width ~320px
- Height: 56px (padding 12px top/bottom to hit 56px; not a spacing-scale value but a layout constant)

### Player Detail Page (`app/player/[id]/page.tsx`)

- Server component (data fetched server-side)
- Player header: `{full_name}` as Heading (20px, semibold) + `{position} · {team}` as Label (14px, silver) inline below
- RecommendationCard renders below the header with `lg` (24px) top gap

### RecommendationCard (`components/RecommendationCard.tsx`)

- `"use client"` component (owns format selector state)
- Background: `#111827`, rounded-xl, padding `lg` (24px), no outer border

**Verdict block (top of card):**
- Verdict word (START / SIT / FLEX) at Display size (36px, weight 700), color per verdict color table
- Score displayed as "Score: 72.4" in Label size (14px), silver, on the same row as verdict word, right-aligned
- Low-confidence flag: amber badge "Low confidence — limited data" in Label size, directly below verdict word

**Scoring format selector (below verdict):**
- Three pills: PPR / half-PPR / standard
- Active pill: background `#004C54`, text white, weight 600
- Inactive pill: background transparent, border `#A5ACAF` 1px, text `#A5ACAF`
- Pill height: 32px, padding 12px horizontal, gap `sm` (8px) between pills
- Changing selection triggers a new API call with `?format=` param; verdict and score update in place

**Reasoning block (below format selector):**
- Section label: "Why" — Label size (14px), silver, `lg` (24px) top margin
- 3-5 plain-English factors as a plain `<ul>` list
- Each item: Body size (16px), white, bullet `·` in silver, `sm` (8px) bottom gap between items

**Signals block (below reasoning):**
- Section label: "Signals" — Label size (14px), silver, `lg` (24px) top margin
- Signal rows as a definition-list-style layout: label left (silver, 14px), value right (white, 16px)
- Rows: Matchup Grade, Injury Status, Practice Status, Snap % (L4W), Target Share or Carry Share (L4W), Projected Points
- Matchup Grade value appended with rank context: e.g., "A (3rd easiest)"
- Injury / Practice Status: colored badge — "Active" in green-500, "Questionable" in amber-500, "Doubtful" in red-400, "Out" in red-500
- Usage rows show 4 weekly values as a compact spark row: "62% · 58% · 71% · 55%" (week1 = most recent, left)
- Projected Points: numeric, e.g., "18.4 pts"

**Freshness stamp (bottom of card):**
- "Updated {relative time}" — Label size (14px), silver `#A5ACAF`
- `sm` (8px) top padding, `xl` (32px) top margin from signals block
- Relative time derived client-side from `updated_at` ISO string

**Loading state (while API fetch in flight):**
- Full card replaced with skeleton: verdict block 3-line pulse, reasoning 4-line pulse, signals 6-row pulse
- All skeletons use background `#1F2937`, rounded, animated `animate-pulse`

**Error state:**
- Full card replaced with error panel (see Copywriting Contract)

### FreshnessStamp (`components/FreshnessStamp.tsx`)

- Pure component, accepts `updatedAt: string` (ISO)
- Renders "Updated 45 minutes ago" or "Updated just now" (< 60s)
- Thresholds: < 60s → "just now"; < 60m → "N minutes ago"; < 24h → "N hours ago"; else → "N days ago"

## Accessibility Contract

- All color pairs must achieve WCAG AA contrast (4.5:1 for normal text, 3:1 for large text/UI components).
  - White `#F9FAFB` on `#0A0A0A` → 18.7:1 (passes AAA)
  - White on `#004C54` → 7.2:1 (passes AAA)
  - `#22C55E` on `#0A0A0A` → 4.8:1 (passes AA)
  - `#EF4444` on `#0A0A0A` → 4.5:1 (passes AA — borderline; use weight 600+ for verdict text)
  - `#F59E0B` on `#0A0A0A` → 4.9:1 (passes AA)
  - `#A5ACAF` on `#0A0A0A` → 4.6:1 (passes AA)
- Touch targets: 44px minimum height for all interactive elements (format pills, autocomplete items, nav links)
- Search input: `aria-label="Search players"`, `role="combobox"`, `aria-expanded` reflects dropdown state
- Autocomplete dropdown: `role="listbox"`, items `role="option"`, `aria-selected` on active item
- Verdict display: `aria-label="Recommendation: {verdict}"` on the verdict element
- Skeleton loading: `aria-busy="true"` on card container, `aria-label="Loading recommendation..."`
- Error state: `role="alert"` on error panel
